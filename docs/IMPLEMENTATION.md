## 为什么先收敛 merge

与 rebase 相比，merge 可以保持原提交身份；预演和恢复边界较明确。
本轮不提供未经逐提交预演验证的 rebase 开关，也不把创建一个 backup ref 宣称为可恢复所有工作区内容。
扩展 rebase 前需要：隔离环境、每步冲突记录、提交映射、保留签名策略说明、ignored 文件覆盖检查、崩溃恢复测试。

## 当前状态机

- 生成计划：检查干净状态 → 解析上下游 → fetch → 复核 → 预演 → 保存计划 → 创建 before/target 引用。
- 无需合并：up_to_date；预演冲突：conflicted；可合并：planned。
- 执行：复核 → 用户确认 → 再复核 → 原子记录 running → 原生 merge。
- 完成：核验分支与目标祖先关系 → 核对父提交、预演树和工作区，保存 succeeded/needs_review/failed 及观测 HEAD；成功时创建 after 引用。
- 异常：尽力保存 interrupted；SIGKILL/断电留下 running，保留恢复引用，明确需要人工判断。
- 恢复：先验证引用，再预览；确认后以预期旧值为零的 update-ref 创建恢复分支，保留当前工作区。
- 未完成操作：仅当记录与当前 MERGE_HEAD/ORIG_HEAD/分支/HEAD/工作区身份匹配时，允许确认后继续或中止。

日志与引用写入不是跨文件事务。程序先保存 preparing 意图，再在一次 Git 引用事务中创建 before/target，最后保存已完成的准备状态；
若在中间终止，缺少恢复引用的计划会拒绝执行，原工作区尚未被 merge 修改。
若 merge 已成功但最终日志尚未写入，可能显示 running；可用 reconcile 只读核对记录的 before/target、当前 HEAD、父提交、结果树与工作区。
工具不会根据不完整日志自动重置状态。

## 并发与诊断边界

bettergit 文件锁覆盖一个 common Git directory，因此 linked worktree 间也互斥；它不锁定所有原生 Git 使用者。
执行前检查不能消除所有外部竞态，最后仍依赖 Git 的引用/索引锁。恢复分支创建使用 compare-and-swap，拒绝覆盖已有分支。
目录采样和 Git 探测在独立会话/进程组运行；结束/超时杀掉仍在同组的子进程，避免昂贵驱动留下孤儿。
POSIX 进程组不是容器或沙箱，主动 setsid 脱离的外部程序不受该清理保证。

诊断的每个判断携带 evidence、interpretation、next_step、confidence；不使用一个毫秒阈值直接宣称“网络错误”。
默认没有网络请求，也不持久化原始命令或 Trace2；显式网络探测调用 Git 自身处理代理/SSH，并仅保留固定错误类别。
本地操作记录包含仓库路径和文件名，但不会保存远端 URL、凭据值、原始配置或文件内容；配置只保存摘要。
