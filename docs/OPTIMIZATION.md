# 同步与诊断深化

本轮落实性能审计后的优先建议，继续使用 Python 标准库，不增加后台常驻服务或修改用户 Shell 配置。

## 已完成的架构变化

### 短期仓库快照

将重复调用 rev-parse、symbolic-ref、config 等改为：

- porcelain v2 一次读取 HEAD、分支和工作区状态，强制检查子模块修改。
- 一次读取配置并计算摘要；一次批量读取相关引用及 Git 解析的上下游信息。
- 排除无关的大型 tag 集合，同时覆盖自定义 fetch 命名空间、大小写分支及本地 upstream。
- 检查采集期间 HEAD 与分支引用是否一致，不一致时拒绝继续。
- 用户确认后重新获取可变状态，自定义合并驱动预演后再次获取快照。
- 仅缓存不可变 OID 对应的树差异；新增路径仍逐次核对实际文件系统。

普通路径的仓库定位合并为一次查询；目录名含换行时回退为独立查询，避免歧义。
备份引用验证从单独 rev-parse 改为使用该阶段的新引用快照。
最终合并验证使用明确的父提交/结果树证明，不再重复查多次祖先关系；验证时不运行签名显示或 notes。

### 引用事务与只读状态核对

准备阶段先持久化 preparing，再通过一次 `update-ref --stdin` 事务创建 before/target 引用。
引用任一方已存在或事务失败时，不会留下仅创建一方的成功事务，计划也不会进入可执行状态。
日志和 Git 引用仍不构成一个跨系统原子事务，因此保留明确的中间状态。

新增：

```sh
bettergit reconcile <ID> --json
```

该命令不更改记录、引用或工作区。它判断实际结果与计划是否一致，并输出证据及下一步建议。
核心分类包括 preparation_incomplete、prepared_unrecorded、not_applied、plan_stale、
matching_unfinished_merge、completed_unrecorded、completed、needs_review、branch_changed、backup_missing、git_busy。

如果记录 running/failed/interrupted，但 HEAD 仍停在操作前且没有明确完成证据，输出 not_applied_or_interrupted；
不会把“未看到结果”解释为“所有原生 Git 子进程都已停止”。索引/引用锁存在时也不擅自删除。
原生外部 Git 进程不受 bettergit 文件锁约束，reconcile 的结果只是采样时的证据，不是全局事务锁或因果归属证明。

### 真正的中断与恢复验证

测试父进程在以下检查点收到就绪信号后，向独立测试 worker 发送 SIGKILL，再新建引擎/重新启动 CLI 读取状态：

1. 准备意图已保存，引用尚未创建。
2. 引用事务完成，准备日志尚未标记就绪。
3. 计划就绪。
4. running 已保存，原生 merge 尚未启动。
5. 原生 merge 返回，结果日志尚未保存。
6. 结果日志已保存，after 引用尚未创建。
7. after 引用已创建，最终日志尚未保存。
8. 最终日志已保存。

快进与分叉合并各执行一次完整矩阵，共 16 个强制终止场景。
每个场景均检查：核对结果可重复，日志字节、索引字节和引用集合不因 reconcile 改变。
还覆盖备份引用事务碰撞、外部分支推进、失效计划、真实 hook 失败，以及固定 6 个种子的二进制/Unicode/换行路径合并。
这不是任意系统调用、磁盘故障或断电模型的穷尽证明；也没有承诺恢复 hook 的外部副作用。

## 诊断变化

- 按 Trace2 事件类别和可执行程序位置识别阶段，不再对任意 URL/路径参数做子串匹配。
- 编辑器、SSH、凭据程序的 shell 包装只做词法解析，不执行字符串。
- 已结束的进程/会话不会保留为活动等待；证据不足仍输出 unknown。
- 显式选择远端探测时预留部分预算，避免本地 status 先耗尽预算。
- 报告/基线附带 Git/Python 版本、平台、样本次数和顺序；环境或采样方式不匹配时不输出耗时比。
- stdout/stderr 改为管道流式读取，任一流超过 4 MiB 就停止同进程组并返回 125；不再把输出无限写入临时文件。

## 准确性验证的范围

受控真实 Git 实验：慢 hook、编辑器等待、凭据 helper 等待、调用假 SSH 的远端传输、人工注入进程启动延迟。
这些实验不连接外部服务器；假 SSH 程序只记录就绪状态并等待，由测试清理。

另有 11 个带标签的合成 Trace2 样本，包含文件系统、SSH、凭据、hook、编辑器、签名等正样本，
以及误导性的远端名/文件名、已结束子进程、已结束会话和无证据负对照。
评估脚本逐类统计 TP/FP/FN、precision/recall，并单列 unknown，不将固定样本的结果当成现实准确率或概率校准。
真实文件系统根因、真实 TLS/DNS 故障、跨平台差异和优化配置的隔离 A/B 实验仍需延伸。

```sh
python3 scripts/test_isolated.py --measure
```

会运行完整测试、真实工作流开销测量、合成故障集评估和独立 Zsh 检查。
最终实测结果见同目录 [optimization-results.json](optimization-results.json)。


## 最终隔离验证结果

2026-10-30 10:46–10:47（Asia/Shanghai），macOS、Python 3.12.4、Git 2.45.2、Zsh 5.9。
73 项 unittest 通过，约 47.14 秒；其中包含上文 16 个 SIGKILL 场景、6 个固定种子合并场景。
独立 Zsh 语法/加载/Enter 绑定/停用检查通过。私有测试配置与受保护用户配置文件指纹均保持不变。

| 场景 | 优化前直接 Git 调用 | 优化后直接 Git 调用 | 调用减少 | 本机单次耗时参考 |
| --- | --- | --- | --- | --- |
| 快进生成计划＋执行 | 69 | 20（11＋9） | 71.01% | 约 0.83s → 0.22s |
| 干净分叉生成计划＋执行 | 74 | 30（16＋14） | 59.46% | 约 0.87s → 0.32s |

耗时是单次本地样例，不计人工确认等待；系统负载和缓存不同，不能据此保证普遍加速比。
调用数目标（快进≤25、分叉≤30）已加入自动回归测试，防止后续功能使开销反弹。

11 个合成样本全部与标签相符，4 个缺少活动证据/负对照样本正确保留 unknown；
该小型固定样本上的零误报、零漏报只说明样本行为，不等于现实世界达到 100% 准确率。
另外 5 个受控真实 Git/进程延迟场景均通过测试。

## 后续仍需推进

优先增加 Linux/不同 Git 版本的运行证据、更多实际故障样本，以及对只读核对的原生并发场景验证。
隔离配置 A/B 实验、逐提交 rebase 预演、PR 阻塞解释、完整工作区生命周期与文件级通用恢复仍未实现。
当前没有新增这些命令来扩大表面功能范围，也没有更改用户全局 Git 或 Shell 配置。
